# Testing and Accessibility Skill

Use this skill when validating a completed slice of work.

## Goals
- validate correctness
- identify edge cases
- assess user-visible clarity
- identify accessibility issues
- produce structured findings

## Testing Focus
- happy path
- malformed input
- unsupported cases
- partial failures
- regressions near the changed area
- accessibility of the implemented flow

## Accessibility Minimum
Check:
- labels and instructions
- keyboard access
- focus behavior
- success/error messaging
- semantic structure

## Reporting Rules
Always report:
- scope tested
- environment
- scenarios
- expected vs actual
- severity
- recommendations
- summary

## PB Lab Bias
- prioritize high-value scenarios first
- focus on current vertical slice
- identify blockers quickly
- document what broader testing remains after the lab
