## Development Commands

### Backend (PHP)

This runs in a docker container using lando so don't try to run these commands directly on the host machine, to run these we need to lando ssh into the container.

`lando ssh && composer <command>`

We can also run these commands using ` vendor/bin/phpunit` with filters or groups as needed.

- `composer test` - Run PHPUnit tests
- `composer test-coverage` - Run PHPUnit tests with coverage report
- `composer standards` - Run PHPCS code style checks
- `composer fix` - Fix PHPCS code style issues automatically

### Frontend (JavaScript/CSS)
- `npm run build` - Build production assets
- `npm run watch` - Build assets and watch for changes (includes BrowserSync)
- `npm run test` or `npm run lint` - Run ESLint and StyleLint
- `npm run lint:scripts` - Run ESLint on JavaScript files
- `npm run lint:styles` - Run StyleLint on SCSS files
- `npm run lint:fix-scripts` - Auto-fix ESLint issues
- `npm run lint:fix-styles` - Auto-fix StyleLint issues

### Testing
- PHPUnit tests: `vendor/bin/phpunit --configuration phpunit.xml`
- Codeception (acceptance/functional): Use `codeception.dist.yml` configuration
- Code coverage reports generated in `./coverage-reports`

### Code Quality

Respect coding style and standards:

- PHPCS ruleset: `phpcs.ruleset.xml` (based on Pressbooks Coding Standards)
- ESLint config: extends `pressbooks-build-tools/config/eslint.js`
- StyleLint config: extends `pressbooks-build-tools/config/stylelint.js`

## Architecture Overview

### Core Structure
Pressbooks is a WordPress multisite plugin for book publishing that outputs multiple formats (PDF, EPUB, web, XML).

**Main Plugin Files:**
- `pressbooks.php` - Main plugin file with initialization
- `inc/class-pressbooks.php` - Core Pressbooks class
- `functions.php` - Global utility functions
- `hooks.php` / `hooks-admin.php` - WordPress action/filter hooks
- `compatibility.php` - PHP/WordPress version checks
- `class-service-provider.php` - Service provider for dependency injection we should use this to register services and classes to make code more testable and modular

When using the service provider, we use the `Pressbooks\Container` class to register services and classes. This allows for better dependency management and makes the code more modular and testable.

### Key Directories

**PHP Code (`inc/`):**
- `admin/` - WordPress admin interface components (metaboxes, dashboard, settings)
- `api/` - REST API endpoints and controllers
- `modules/` - Major features (export, import, theme options, search & replace)
- `shortcodes/` - Custom shortcode implementations
- `htmlbook/` - HTMLBook format parsing and validation
- `covergenerator/` - Book cover generation functionality
- `cloner/` - Book cloning/copying functionality

**Frontend Assets (`assets/`):**
- `src/` - Source files for scripts and styles
- `dist/` - Compiled/built assets (generated by webpack.mix.js)

**Templates (`templates/`):**
- Blade templates for admin interfaces and exports
- Organized by feature (admin, export, metaboxes, etc.)

**Tests (`tests/`):**
- PHPUnit tests (`test-*.php` files)
- Codeception acceptance/functional tests
- Test data in `tests/data/`

### Key Classes and Namespaces

**Core Classes:**
- `Pressbooks\Pressbooks` - Main plugin class
- `Pressbooks\Book` - Book-specific functionality
- `Pressbooks\Container` - Dependency injection container (Illuminate/Container)
- `Pressbooks\Metadata` - Book metadata handling

**Export/Import System:**
- `Pressbooks\Modules\Export\Export` - Base export functionality
- `Pressbooks\Modules\Import\Import` - Base import functionality
- Format-specific classes in respective subdirectories (epub, prince/pdf, xhtml, etc.)

**Admin Interface:**
- `Pressbooks\Admin\Dashboard\*` - Dashboard components
- `Pressbooks\Admin\Metaboxes\*` - Custom meta boxes
- `Pressbooks\Admin\Fields\*` - Form field types

### Build System
- **Laravel Mix** (`webpack.mix.js`) for asset compilation
- Compiles individual JS/SCSS files to `assets/dist/`
- BrowserSync proxy configured for `https://pressbooks.test/wp-login.php`
- Copies vendor libraries and fonts to dist folder

### Dependencies
- **PHP 8.2+**, WordPress 6.6.1+
- **Laravel Components** (Container, View, etc.) for modern PHP patterns
- **Prince XML** or **DocRaptor** for PDF generation
- **HTMLawed** for HTML sanitization
- **SCSS-PHP** for Sass compilation

### Testing Strategy
- **PHPUnit** for unit tests of PHP classes
- **Codeception** for acceptance/functional testing
- Tests require WordPress multisite environment
- Coverage excludes template directories

### WordPress Integration
- Designed specifically for WordPress **multisite**
- Theme system integration (book themes vs. root themes)
- Custom post types for book content
- Network-level and book-level settings
- Session management for multi-step processes

## Key Concepts

**Book vs Network Context:**
- Different admin interfaces and themes based on whether user is in a book or network context
- `Book::isBook()` determines current context

**Export Pipeline:**
- Multi-format export system with shared base classes
- Each format (PDF, EPUB, etc.) extends base export functionality
- Background processing for long-running exports

**Theme Architecture:**
- Separate theme directories for book themes vs. network/root themes
- Theme filtering based on context
- CSS-based formatting for different output formats

Exclude any files or directories that are not relevant to the core functionality of the plugin, such as:

- `node_modules/` - Node.js dependencies
- `vendor/` - Composer dependencies
- `coverage/` - Code coverage reports
